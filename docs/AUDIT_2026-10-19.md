## 02 — Autentifikatsiya va ruxsatlar

### Login, parol, JWT, refresh

- **[OK] Parol:** bcrypt (`core/security.py:18`), 72-bayt chegara ham hash'da ham schemada (`schemas/auth.py:16-21`).
- **[OK] Foydalanuvchini aniqlab bo'lmaydi (enumeration yo'q):** notanish email, noto'g'ri parol va o'chirilgan user bir xil 401 qaytaradi (`services/auth.py:80-85`); notanish user uchun dummy-hash timing tekislanadi (`core/security.py:35-36`).
- **[OK] Login limiter:** PostgreSQL `login_attempts` jadvalida, 5 xato / 15 daqiqa, HMAC(IP+email) kalit, advisory lock, 429 + `Retry-After` (`services/auth.py:25-70`). [LOW] client IP bo'yicha — IP almashtirish bilan chetlab o'tiladi.
- **[OK] JWT:** faqat HS265 pinlangan (`core/config.py:25,60-61`), tokenda rol YO'Q (rol har so'rovda DB'dan olinadi — `core/security.py:91-95`), secret ≥32 bayt majburiy (`core/config.py:32-37`).
- **[OK] Refresh:** HttpOnly + SameSite=Lax + path=`/api/v1/auth` (`routers/auth.py:17-30`); har ishlatishda rotatsiya; DB'da faqat SHA-256 xesh; logout, o'chirish va parol almashtirishda revoke qilinadi.
- **[MEDIUM·deployment] `Secure` flagi shartli** — `request.url.scheme` ga bog'liq (`routers/auth.py:27`). TLS proxy orqasida `X-Forwarded-Proto` sozlanmasa flag yo'qoladi; production'da tekshirish kerak.
- **[LOW]** Parol uchun minimal uzunlik 1 (siyosat yo'q); refresh token o'g'irlanganini aniqlash (reuse detection) yo'q.

### Rollar va master scope

- **[OK] Barcha 19 router ruxsat dependency'siga ega.** Public faqat login/refresh/logout va `/health` (ma'lumot bermaydi). Wialon o'z ingest tokeni bilan. Rollarga yuqori ruxsat berilmaydi (`services/permissions.py:32-34`).
- **[OK] Admin himoyasi:** API orqali yangi admin yaratish bloklangan, demotion bloklangan, oxirgi aktiv admin va o'zini o'chirish himoyasi, `users.set_active` alohida ruxsat (`services/users.py:50-125`).
- **[OK] Master scope SQL darajasida** (server tomonidan autentifikatsiyalangan user'dan olinadi, klient parametriga ishonmaydi): work_orders, maintenance, tmc_documents, assets (o'qish), references (o'qish), nomenclature, ml. Dashboard/analytics — service qatlamida majburlanadi (baribir server tomonda). Begona section → 404, status tekshiruvlaridan OLDIN.
- **[MEDIUM·conditional] Yozish/o'chirish yo'llarida master scope YO'Q:** buyurtma o'chirish (`services/work_orders.py:426`), asset PATCH/DELETE/probeg (`routers/assets.py:114-154`), references yozuvlari (`services/references.py:200-300`). Hozingi standart rollarda xavfsiz (master'da bu ruxsatlar yo'q), lekin admin ruxsatlarni kengaytirsa xavfli bo'ladi.

### WebSocket, eksport, Wialon, bypass

- **[OK] /ws:** ulanishda JWT auth (10 s ichida), master faqat o'z section eventlarini oladi (PG trigger `schema.sql:504-530` orqali section_ids), har 30 s da ruxsat qayta tekshiriladi (`routers/realtime.py:111-129`).
